QUESTION (open item 14 / H14, journals/ija_draft.md:252-261; previous step h14e_advect.log, journals/new_analyses_h14e_advect.md):
h14e measured the eddy slowdown S50 at l/w = 10 on a six-point ladder, D_mol/D_eff = 1/8 ... 1/256: S50 = 5.76, 7.71, 10.27, 13.05, 15.28, 18.07
[95% 17.66..18.52] (h14e_advect.log). The local exponent went 0.42, 0.41, 0.34, 0.23, 0.24 [95% 0.19..0.29] (h14e_advect.log:73); the pre-registered
label for q(128 -> 256) was UNDECIDED (:109), the constant slope q 0.36 was EXCLUDED (:110), the local-slope label UNRESOLVED (:111). A log law
S50 = -1.98 + 3.59 ln r fits the six points with rms 0.20, a single power law (q 0.33) with rms 0.66 (:79-80; both descriptive, post hoc).
Extrapolated to the real ratio 1e9 the two pictures part completely: the log law gives S50 = 72 [69..76] (f = 17 S = 1230, below the Early Earth edge
f = 2400-2600, S* = 141-153), a power law held at the 128 -> 256 slope gives 305 / 703 / 1567 at q 0.19 / 0.24 / 0.29 (:88-94). One more doubling
cannot tell them apart. h14f adds ONE cell four doublings further out, V4096_10 (1/4096, l/w 10), and asks whether the slope keeps falling.
Same model, same flow family, same per-case gamma rule, same statistics; 1/8 ... 1/128 are reloaded from h14d_advect_raw.pkl and 1/256 from
h14e_advect_raw.pkl, NOT rerun.

    (a) S = 1 per job (3 runs per job, one per Delta) instead of 7, so one worker holds about 0.8 GB, and hold = 90 t17 instead of 60, since the
        clearing times scale with S50 (at 1/256 the longest clearing was 2.06 x the median, h14e_advect_raw.pkl).
    (b) The shear kick is a numba loop, h14f_advect.nkick, put in place of h14b_advect.kick inside each worker. It computes the same cubic
        Lagrange weights with the same numpy float32 expressions and sums the four terms in the same order. Its self-check asserts it is
        bitwise equal to h14b_advect.kick on random fields for both axes (including shifts of hundreds of cells), and that a tiny run_case
        gives identical outputs with either kick. The numpy kick needs about 2 GB of index temporaries per worker at N = 4021 and took
        1.8-23 s per call (throwaway timing); the numba one 0.2-0.3 s.
  - Ratio exponent q(a -> b) = ln(S50_b / S50_a) / ln(r_b / r_a), paired by bootstrap replicate index (bs[:, 0] of each cell), as h14d / h14e.
    The new one is q(256 -> 4096) = ln(S50(V4096_10) / S50(V256_10)) / ln 16.
  - Delta q = q(256 -> 4096) - q(128 -> 256), paired over the same replicates.
